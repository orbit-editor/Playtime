# Playtime 设计文档（第一版）

- 状态：需求与设计已确认（2026-11-21），下一步编写实施计划
- 许可证：AGPL-3.0
- 仓库：https://github.com/orbit-editor/Playtime
- 本文档是第一版（v0.1）的设计基线。实现中与本文不符的地方，先改本文再改代码。

---

## 1. 背景与目标

教室里的教学一体机（大屏）平时主要用来放课件，课间十分钟基本闲置。Playtime 把这块屏幕变成课间十分钟的「知识练习场」：

- 孩子在屏上玩短小的知识小游戏，练的正是课上刚学的东西，攒小红花；
- 班主任在同一个工作台里发表格通知、管名单、审批兑换；
- 任何一个老师把自己做的游戏或课件分享出来，别人像装插件一样装上就能用；
- 全部跑在教室本机，断网也能用。

### 1.1 三条不能让的原则

1. 本地优先：装在学校机器上自己跑，不依赖任何云端账号。网络只用于「装扩展 / 刷新清单」这类可选动作。
2. 孩子零门槛：不注册、不设密码。学号或拼音首字母即可认领自己，三秒内开始玩。
3. 老师可扩展：游戏和课件都是扩展。扩展是一堆普通文件加一份说明，任何会写网页的老师都能做。

### 1.2 第一版的成功标准

| # | 验收项 | 判定方式 |
|---|---|---|
| 1 | 装好后无配置进入首页 | 装完点开即见首页，不需要任何账号 |
| 2 | 一分钟内完成认领到入账 | 认领 → 玩一局 → 看到小红花到账，全程不超过一分钟 |
| 3 | 手机可改通知 | 手机扫码改一条通知，大屏首屏立即更新 |
| 4 | 一键装扩展 | 从清单里把一个扩展装上并玩到 |
| 5 | 数据可搬运 | 导出备份，换机器导入后数据完整 |

## 2. 使用者与场景

| 角色 | 场景 | 设备 | 诉求 |
|---|---|---|---|
| 学生 | 课间 10 分钟，轮流到屏前 | 一体机大屏（触摸） | 快进入、好玩、能看到自己的花 |
| 班主任 | 早读前发通知、课后批兑换、月末导数据 | 一体机（大屏输密码）或自己手机 | 打字舒服、不用学 |
| 任课老师 | 想给本班加一个自己做的游戏 | 自己的电脑 + 一体机 | 做起来简单、给出去简单 |
| 项目维护者 | 维护扩展清单、审上架 | GitHub | 流程清楚、能拒绝 |

一台一体机固定服务一个班。跨班共用、走班场景不在第一版。

## 3. 范围

第一版做：

- 首次启动引导（建班级、设年级、导入名单、设 4 位密码）
- 大屏首页（通知条、游戏墙、小红花看板、老师入口）
- 学号 / 拼音首字母认领
- 口算闯关（示例扩展，随平台内置）
- 一局结算、小红花入账、每日上限
- 个人榜 / 班级看板
- 我的花、兑换提交
- 工作台五个页签：通知、班级、奖励、扩展、数据
- 手机版工作台（扫码进入，全部功能可用）
- 扩展安装（清单）、启用 / 停用 / 卸载
- 扩展沙箱与运行时接口
- 备份导出 / 导入
- Windows 与 Android 两个安装包

第一版不做：

- 知识点讲解、课件播放器
- 家长端、消息推送
- 跨设备 / 跨班数据同步、账号体系
- 多班共用一台机器
- 复杂排行榜（周榜趋势、勋章体系）
- 课堂模式（上课自动锁屏）——已确认不做，随时可玩

## 4. 体验设计

### 4.1 首次启动引导

1. 欢迎页：一句话说明这是什么，一个「开始」按钮。
2. 建班级：班级名称（如「三年级二班」）、年级（1–9）、学校名（可选，仅用于显示）。
3. 导入名单：粘贴一段（每行「学号 姓名」或「姓名」）、从 Excel 复制、或先跳过。
4. 设密码：4 位数字，两次确认。提示「这是老师进工作台的密码，不要告诉学生」。
5. 完成页：显示局域网地址与二维码，提示「用手机扫这个码就能进工作台」，并给出「去打一局」。

引导可跳过；跳过则进入「待配置」首页，点老师入口会重新进入引导。

### 4.2 大屏首页

逻辑分辨率 1920×1080，按窗口等比缩放（4K 屏上整体放大，布局不变）。

- 顶部通知条（通栏，高约 72px）：最新一条通知的标题 + 一行摘要；多条时右侧显示「还有 N 条」，点开列表。无通知时整条收起。
- 中间游戏墙：卡片网格，4 列自适应；每张卡片是扩展的图标、名字、一行说明。停用的扩展不显示。
- 右上角小红花看板：本班今日获得数 + 本周总数；点一下进入看板页（个人榜、最近发放流水）。
- 右下角齿轮：直径 56px，低对比度（与背景同色系，只有轮廓），点击进入密码框。学生不会注意。

### 4.3 认领

点游戏卡片后弹出认领浮层：

- 大键盘（数字加字母），输入学号或拼音首字母，支持模糊匹配；
- 实时给出候选（最多 6 个）：头像色块、姓名、学号；
- 只有一个候选时直接确认；选错可以「不是我」返回；
- 认领状态保持 5 分钟（课间连着玩几局不用重复输），回首页或超时失效。

拼音首字母在名单导入时自动生成（李小明 → lxm），多音字以常用读音为准，允许老师手改。

### 4.4 一局口算闯关

- 60 秒一局，顶部倒计时条；
- 按班级年级出题：1–2 年级 20 / 100 以内加减，3–4 年级乘除与混合，5–6 年级分数小数，7–9 年级有理数与简单方程；
- 答题：四选一或大数字键盘，答对闪绿得分，答错闪红并扣 3 秒；
- 连对 3 题起触发连击，得分系数逐级提高，顶部显示「连击 x3」；
- 音效：答对短促上行音、答错下行音、连击叠加音高，用 WebAudio 合成，不引入音频素材；
- 结束：结算面板显示答对题数、最高连击、获得花朵数（1–3 朵），3 秒后回首页。

### 4.5 小红花规则

- 一局基础 1 朵；正确率 ≥ 80% 得 2 朵；≥ 95% 且 15 题以上得 3 朵；
- 单人每日上限 20 朵，全班每日上限 200 朵；超限仍可玩，结算显示「今天的花已经收好啦」；
- 所有发放写流水（谁、哪个游戏、为什么、几朵），余额由流水汇总，不单独存字段；
- 花不可为负，撤销通过冲正流水实现。

### 4.6 我的花与兑换

- 从首页看板进入，选自己（同认领流程）；
- 显示总花数、今日获得、可兑换奖励（够花亮起，不够灰显「还差 N 朵」）；
- 点「兑换」→ 二次确认 → 生成待批单，提示「等老师批」；
- 待批单在工作台可见；通过自动扣花，驳回退单并给出一条提示。

### 4.7 老师工作台

入口：大屏右下角齿轮 → 4 位数字键盘 → 进工作台。连续输错 5 次锁定 60 秒。

工作台顶部五个页签，页签内都是「列表加编辑」的简单结构。

1. 通知：列表、新建、编辑、删除、置顶；正文多行文本，支持简单换行。右上角「用手机改」按钮，点开显示二维码与局域网地址。
2. 班级：班级名与年级编辑；名单表格（学号、姓名、拼音、启用开关）；粘贴导入；导出 CSV；清空名单需二次确认。
3. 奖励：奖励项列表（名称、所需花朵、每周限量、启用）；兑换单列表（待批 / 已通过 / 已驳回），待批一键通过或驳回。
4. 扩展：已装扩展列表（图标、名字、版本、作者、开关、卸载）；「刷新清单」按钮；清单里未装的显示「安装」。
5. 数据：导出备份（下载 zip）、导入备份（选择文件，二次确认）、显示数据占用与最近一次备份时间。

### 4.8 手机版

同一个前端应用的 /m 路由，按手机宽度重排：首屏是通知列表加快捷入口（发通知、批兑换、看班级）。进入方式：

- 扫码（二维码带一次性口令，5 分钟有效）；
- 输入地址后输入 4 位密码（同一套密码）。

手机端能改全部内容。手机与大屏实时同步（服务端推送事件，大屏收到后刷新对应区域）。

### 4.9 扩展的安装体验

- 扩展页默认展示清单：图标、名字、一句话说明、作者、适用年级、大小；
- 点「安装」→ 显示进度 → 装完直接出现在首页游戏墙，并提示「装好了，去玩一局」；
- 失败给出人话原因（网络不通、校验不通过、版本不兼容、名字重复）。

## 5. 系统架构

### 5.1 组成

    教室一体机
    ┌──────────────────────────────────────────────┐
    │ 外壳进程（启动器）                             │
    │  - Windows：playtime.exe 启动服务 + 打开 Edge  │
    │  - Android：Activity + WebView + 前台服务      │
    │                                               │
    │ 本地服务 playtime（Go，监听 0.0.0.0:8730）     │
    │  - 静态资源（内嵌前端构建产物）                 │
    │  - JSON API                                   │
    │  - SQLite（数据）                              │
    │  - 扩展宿主（文件服务、安装器、校验）            │
    │  - 事件推送（SSE）                             │
    └──────────────────────────────────────────────┘
              ▲                        ▲
              │ 本机 127.0.0.1          │ 局域网 http://<ip>:8730/m
         大屏 UI（浏览器 / WebView）   老师手机（浏览器）

选型说明（给后续贡献者）：

- 后端用 Go 单二进制：Windows 打包只需一条交叉编译命令，产物无运行时依赖；纯 Go 的 SQLite 驱动（modernc.org/sqlite）避免 CGO，交叉编译零障碍。
- 不用 Electron / Tauri：Android 端两个都用不了或代价过高；而 Windows 端只需要一个无地址栏的全屏窗口，Edge 应用模式（--app=URL --start-fullscreen）已足够，且不增加几十兆运行时。
- 前端一套代码两个形态：大屏与手机是同一 SPA 的两套路由与样式，避免两份界面逻辑。
- Android 外壳用 Kotlin：通过 gomobile 把 Go 服务编译成 AAR，Activity 起一个 WebView 指向 127.0.0.1:8730，前台服务保证息屏后服务不被杀。

### 5.2 端口与地址

- 首选 8730，被占用则依次试 8731–8739，最终写入数据目录下的 runtime.json（含端口与启动时间）。
- 局域网地址枚举所有非回环 IPv4，按 192.168 / 10. / 172.16–31 优先级排序，默认取第一个，可在工作台手动切换（多网卡时）。
- 二维码内容：http://<ip>:<port>/join?t=<一次性口令>

### 5.3 数据目录

    data/
      playtime.db          SQLite
      runtime.json         运行状态（端口、口令有效期）
      backups/             自动备份（每天一次，保留 7 份）
      plugins/
        <plugin-id>/      解压后的扩展（含 playtime-plugin.json）
      uploads/             导入的临时文件（定时清理）
      logs/                滚动日志（保留 7 天）

Windows 默认放在 exe 同级的 data/（便携，拷走整个文件夹等于换机器）；目录不可写时退到 %LOCALAPPDATA%\Playtime。Android 放在应用私有目录。

### 5.4 数据模型

    classes       (id, name, grade, school_name, pin_hash, created_at)
    students      (id, class_id, sid, name, pinyin, enabled, created_at)
    notices       (id, title, body, pinned, created_at, updated_at)
    rewards       (id, title, cost, weekly_limit, enabled, created_at)
    redeems       (id, student_id, reward_id, status, created_at, decided_at, decided_by)
    plays         (id, student_id, plugin_id, started_at, ended_at, score, correct, total, flowers)
    flower_ledger (id, student_id, delta, reason, ref_id, created_at)
    plugins       (id, name, version, author, manifest_json, enabled, installed_at, source)
    settings      (key, value)
    sessions      (token, role, expires_at)

余额 = sum(flower_ledger.delta)，不做冗余字段。

### 5.5 接口

    GET  /api/bootstrap                     首页数据（班级、通知、扩展、看板）
    POST /api/identify   {q}                认领候选
    POST /api/play/start {student_id, plugin_id}         开一局，返回局 id 与题目种子
    POST /api/play/finish{session_id, score, correct, total, elapsed}   结算，返回花朵
    GET  /api/leaderboard?range=week|today
    GET  /api/students/:id/flowers          个人花与可兑列表
    POST /api/redeem     {student_id, reward_id}
    GET  /api/events                         SSE：notice / flowers / redeems / plugins 变更
    GET  /join?t=                            手机入口
    POST /api/auth/pin   {pin}               换取会话
    GET/POST/PUT/DELETE /api/admin/{notices,students,rewards,plugins}
    POST /api/admin/redeems/:id/decide {approve}
    GET  /api/admin/backup                   下载 zip
    POST /api/admin/restore                  上传 zip
    GET  /ext/<plugin-id>/...                扩展静态资源

### 5.6 鉴权

- 大屏访问来自回环地址时视为设备本身，读接口免鉴权；写接口要求设备令牌（启动时随机生成，写入 runtime.json，服务端注入页面）。
- 老师：4 位密码 → 服务端签发 32 字节随机 token，HttpOnly Cookie，7 天有效；连续错误 5 次锁 60 秒（按来源 IP 计数）。
- 手机：扫码带一次性口令（5 分钟、一次性），换取会话 Cookie；也可直接输密码。
- 写接口做 CSRF 防护（SameSite=Lax 加自定义头校验）。

## 6. 扩展机制

### 6.1 扩展是什么

一个文件夹，至少有 playtime-plugin.json 与入口 HTML。没有任何构建要求，可以就是一个 HTML 加几个图片。

    my-math-game/
      playtime-plugin.json
      index.html
      style.css
      icon.svg

### 6.2 说明文件

    {
      "id": "com.example.mental-math",
      "name": "口算闯关",
      "version": "1.0.0",
      "author": "张三",
      "description": "一分钟口算，按年级出题",
      "grades": [1, 2, 3, 4, 5, 6, 7, 8, 9],
      "entry": "index.html",
      "icon": "icon.svg",
      "scoring": true,
      "minPlatform": "0.1.0"
    }

- id 全局唯一，反域名格式，安装时校验格式与唯一性。
- scoring 为 true 时结算发花；课件类扩展设为 false。

### 6.3 运行方式（沙箱）

- 平台把扩展挂到 /ext/<id>/，前端用 iframe sandbox="allow-scripts" 加载入口。
- 沙箱 iframe 是不透明源，读不到父页面、读不到本机文件、发不了跨域请求。
- 与父页面只通过一个 MessageChannel 端口通信：父页面加载完成后把端口转移给 iframe，扩展侧用 Playtime.init() 拿到 API 对象。
- 平台对每条消息做结构与数值校验（分数不超过题量、时间不能为负）。

### 6.4 扩展可用接口

    Playtime.ready()                      声明已加载
    Playtime.context()                    当前班级、年级、学生（只给姓名与学号）
    Playtime.submitResult({correct,total,elapsed,score})
    Playtime.showToast(text)
    Playtime.storage.get(key) / set(key,value)    命名空间隔离、上限 64KB
    Playtime.exit()                       结束并回首页

不在白名单里的能力一律没有。

### 6.5 清单与安装

- 清单是主仓库里的 plugins/index.json，通过 raw.githubusercontent.com 拉取，每小时最多刷新一次。
- 每条记录：id、name、description、author、repo、commit、sha256、icon、size。
- 安装：下载 https://codeload.github.com/<owner>/<repo>/zip/<commit>，校验 SHA-256，解压到 plugins/<id>/，校验说明文件后落库。
- 解压拒绝路径穿越、拒绝符号链接、限制总大小 50MB 与文件数 2000。
- 上架要维护者在 PR 里合并一条记录；每条记录都带 zip 的 SHA-256，安装时校验，防中途被换。
- 已装扩展可离线使用；刷新清单与安装需要网络。

### 6.6 内置扩展

口算闯关按上述全部规则写成扩展，随二进制内嵌，首次启动解压到 plugins/。它是第一个示范，也是文档里的范例。

## 7. 平台适配

Windows：

- 产物 playtime.exe（单文件，约 20–30MB）。
- 启动：起服务 → 用 Edge 应用模式打开 http://127.0.0.1:<port>/?k=<设备令牌>；找不到 Edge 则用默认浏览器。
- 窗口全屏、无地址栏；退出方式：任务栏右键退出，或工作台里的「退出程序」。
- 开机自启：安装向导里可选，默认开启（写当前用户启动项）。
- 交叉编译：在 macOS / Linux 上用 GOOS=windows GOARCH=amd64 产出，CI 里再跑一次冒烟测试。

Android：

- 产物 playtime.apk（arm64-v8a 为主，兼容 armeabi-v7a）。
- 外壳：单 Activity，全屏沉浸、锁定横屏，WebView 指向本机服务；前台服务常驻（通知栏一条「Playtime 运行中」）。
- 权限：仅网络与前台服务；不需要存储权限。
- 返回键：首页二次确认才退出；游戏内返回游戏墙。
- 系统 WebView 低于 100 时给出升级提示。

通用：

- 触摸优先：可点区域不小于 48×48 逻辑像素。
- 4K 屏：整体 CSS 缩放，布局按 1920×1080 设计。
- 长期运行：服务端每小时自检（磁盘、数据库完整性），异常写日志。
- 字体：用系统字体栈（Windows 微软雅黑、Android 系统无衬线），不打包商业字体。
- 图标：统一 lucide 线性图标，禁止 emoji。

## 8. 安全与隐私

- 学生姓名、学号只存在本机数据库，不上传任何服务器；平台自身没有遥测。
- 手机端与扩展访问都走本机服务；扩展被沙箱隔离，无法读取数据库文件或发起网络请求。
- 4 位密码有穷举风险，靠「5 次锁 60 秒」与「仅限校内网」缓解；文档明确建议不要暴露到公网。
- 备份 zip 含学生名单，导出时提示妥善保管；导入时校验版本与完整性。
- 依赖只取官方 Go 模块与 npm 包并锁版本；CI 跑 govulncheck 与 npm audit。

## 9. 失败与降级

| 情况 | 表现与处理 |
|---|---|
| 手机与一体机不在同一网段（学校 AP 隔离） | 二维码旁给「连不上？」入口，展开三步热点引导，二维码切换为热点网段地址 |
| 断网 | 首页、游戏、工作台正常；扩展页提示「当前离线，装不了新扩展」 |
| 端口被占用 | 自动顺延，工作台显示实际端口 |
| 数据库损坏 | 启动时检测，用最近备份恢复，保留损坏文件 |
| 扩展崩溃 | iframe 加载超时 10 秒或报错，显示「这个游戏没打开」，不影响其他功能 |
| 名单为空 | 首页提示「先让老师导入名单」，老师入口高亮 |
| 4K 屏卡顿 | 前端降级：关闭阴影与模糊，缩短动画 |

## 10. 测试与验收

- Go 单元测试：计分与发花规则、每日上限、认领匹配（学号 / 拼音 / 重名）、鉴权与锁定、备份导出导入、解压安全（路径穿越、大文件、符号链接）。
- 前端端到端（Playwright）：首次引导 → 导入名单 → 认领 → 玩一局 → 到账 → 兑换提交 → 工作台审批 → 手机端改通知 → 大屏同步。
- 扩展沙箱测试：恶意扩展尝试读父页面、发请求、篡改分数，全部失败且不崩。
- 打包验收：CI 产出 Windows exe 与 Android apk；Windows 在 CI 的 windows runner 上启动并请求 /api/bootstrap 成功；Android 本机构建并装到模拟器跑通首页。
- 人工验收：在真实一体机上跑一遍触摸与 4K 显示。

## 12. 开放问题

1. 学校 Wi-Fi 是否禁止设备互访，需要现场验证；热点方案作为兜底。
2. 一体机的 Android 版本与 WebView 版本需要实测，可能影响最低支持版本。
3. 是否需要开机自启由学校统一管控，先做成可选。
4. 扩展清单需要至少一个第三方扩展才有意义，第一版先用我们自己的口算充当清单第一条。
